# Content QA

## Story

- [ ] Audience and purpose are clear.
- [ ] The deck answers the audience's likely questions in a logical order.
- [ ] The opening establishes context/importance.
- [ ] Each slide contributes something distinct.
- [ ] The ending gives a useful conclusion or next step.

## Accuracy

- [ ] Claims are supported by source material.
- [ ] Numbers match source.
- [ ] Units are correct.
- [ ] Dates/versions are correct.
- [ ] Architecture arrows/relationships match the system.
- [ ] Commands/code examples are syntactically plausible and contextually correct.
- [ ] No unsupported marketing claims were introduced.

## Terminology

- [ ] Terms are consistent.
- [ ] Acronyms are explained on first use when audience may not know them.
- [ ] Product/component names match source.
- [ ] "Tool", "Resource", "Agent", "RAG", "MCP", etc. are not used interchangeably.

## Teaching Quality

- [ ] Difficult ideas are explained before advanced consequences.
- [ ] Diagrams have a stated interpretation.
- [ ] Examples are concrete.
- [ ] Speaker notes add explanation rather than duplicate slide text.
- [ ] Common failure/misunderstanding is covered where useful.
