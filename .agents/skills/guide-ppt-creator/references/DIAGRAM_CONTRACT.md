# Diagram Contract

Use this for architecture, workflow, state, sequence, hierarchy, dependency, or data-flow diagrams.

## Question the Diagram Must Answer

Example:
"How does user input travel through the Agent Runtime and reach tools/RAG?"

## Diagram Type

Choose one:
- architecture
- data flow
- process flow
- sequence
- state machine
- hierarchy
- comparison
- lifecycle
- deployment
- network topology

- containers
- nodes
- arrows
- dashed lines
- risk/approval gates

## Editable Output

Prefer editable PowerPoint shapes/connectors for simple diagrams.

Use raster/vector image generation only when it materially improves the visual and the content does not need frequent editing.

## Diagram QA

- [ ] Flow direction is obvious.
- [ ] Arrow direction matches actual behavior.
- [ ] No crossed connectors when avoidable.
- [ ] Labels are readable.
- [ ] Same concept uses same visual treatment.
- [ ] External vs internal systems are distinguishable.
- [ ] Diagram answers the stated question.
