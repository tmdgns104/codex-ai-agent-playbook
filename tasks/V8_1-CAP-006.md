## 목적

CAP-005에서 검증한 선택 Skill staging을 실제 Codex Skill discovery 규칙과 연결하는 pre-session bridge를 구현합니다.

이번 Task는 **새 Codex 세션 시작 전 준비/검증/cleanup prototype**입니다. 실행 중 세션 hot-reload를 가정하지 않습니다.

## 확인된 Codex 동작

OpenAI Codex 현재 구현 기준:

- 사용자 Skill root에 `~/.agents/skills`가 포함됨
- Git/project root부터 현재 `cwd`까지 각 디렉터리의 `.agents/skills`를 discovery root로 탐색
- Skill이 구성되면 세션 초기 input에 Skill metadata가 포함됨
- Codex CLI는 `-C/--cd <DIR>`로 working root를 지정할 수 있음
- `--add-dir <DIR>`로 추가 writable directory를 연결할 수 있음
- TUI `/skills`에서 현재 사용 가능한 Skill을 확인할 수 있음

따라서 전역 `~/.agents/skills`를 변경하지 않고 repo 하위 session 전용 cwd에 `.agents/skills`를 만들 수 있습니다.

## Bridge 구조

```text
<repo>/
  .agents/skills/                    # 기존 Core Skill, 수정 안 함
  .playbook-runtime/
    <session>/
      activation.json
      bridge.json
      cwd/
        .agents/
          skills/
            security-review/
              SKILL.md
            testing/
              SKILL.md
            root-cause-debugging/
              SKILL.md
```

Codex 시작 예:

```cmd
codex -C .playbook-runtime\<session>\cwd --add-dir .
```

`cwd`는 repository 하위이므로 Codex loader가 project root -> cwd 사이의 `.agents/skills`를 탐색할 때 bridge Skill root를 발견할 수 있습니다.

## 핵심 원칙

1. pre-session only
2. 실행 중 hot-reload 주장 금지
3. 전역 `~/.agents/skills` 변경 금지
4. repository root `.agents/skills` 변경 금지
5. 선택된 eligible optional Skill만 bridge에 노출
6. Skill 본문 전체 Library를 discovery path에 복사하지 않음
7. bridge target은 반드시 repository 하위
8. Git repository root 확인
9. CAP-005 SHA256 integrity 유지
10. 실제 Codex 실행은 자동화하지 않음
11. launch command만 생성
12. `/skills`로 실제 discovery를 사람이 확인
13. cleanup은 managed session만 삭제
