## 목적

CAP-005에서 검증한 선택 Skill staging을 실제 Codex Skill discovery 규칙과 연결하는 pre-session bridge를 구현합니다.

이번 Task는 **새 Codex 세션 시작 전 준비/검증/cleanup prototype**입니다. 실행 중 세션 hot-reload를 가정하지 않습니다.

## 확인된 Codex 동작

OpenAI Codex 현재 구현 기준:

- 사용자 Skill root에 `~/.agents/skills`가 포함됨
- Git/project root부터 현재 `cwd`까지 각 디렉터리의 `.agents/skills`를 discovery root로 탐색
- Skill이 구성되면 세션 초기 input에 Skill metadata가 포함됨
- Codex CLI는 `-C/--cd <DIR>`로 working root를 지정할 수 있음
- `--add-dir <DIR>`로 추가 writable directory를 연결할 수 있음
- TUI `/skills`에서 현재 사용 가능한 Skill을 확인할 수 있음

따라서 전역 `~/.agents/skills`를 변경하지 않고 repo 하위 session 전용 cwd에 `.agents/skills`를 만들 수 있습니다.

## 구현

추가:

```text
harness/activation/discovery_bridge.py
harness/activation/test_discovery_bridge.py
```

Bridge 구조:

```text
<repo>/
  .agents/skills/                    # 기존 Core Skill, 수정 안 함
  .playbook-runtime/
    <session>/
      activation.json
      bridge.json
      cwd/
        .agents/
          skills/
            security-review/
            testing/
            root-cause-debugging/
```

CAP-005 materializer를 재사용한 뒤 managed `skills/`를 `cwd/.agents/skills/`로 이동하고 activation manifest destination을 갱신합니다. SHA256 status 검증은 그대로 재사용합니다.

## CLI

Prepare:

```cmd
python harness\activation\discovery_bridge.py prepare --root . --task "<task>" --target .playbook-runtime --session <id>
```

Status:

```cmd
python harness\activation\discovery_bridge.py status --target .playbook-runtime --session <id>
```

Launch command:

```cmd
python harness\activation\discovery_bridge.py command --target .playbook-runtime --session <id>
```

Cleanup:

```cmd
python harness\activation\discovery_bridge.py cleanup --target .playbook-runtime --session <id>
```

## Launch 계약

Bridge는 Codex를 자동 실행하지 않습니다. 다음 argv만 생성합니다.

```text
codex -C <repo>/.playbook-runtime/<session>/cwd --add-dir <repo>
```
