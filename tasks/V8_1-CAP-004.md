## Skill 계약

각 optional Skill은 최소:

```text
SKILL.md
```

를 가지며 frontmatter에:

- `name`
- `description`

을 포함합니다.

본문은 다음을 중심으로 구성합니다.

- 언제 사용
- 언제 사용하지 않음
- 최소 workflow
- Evidence/stop 조건
- 다른 Capability로 넘길 조건

## Skill별 정책

### security-review

참고 아이디어:

- auth/authz
- input validation
- secret handling
- injection
- sensitive data
- dependency/security boundary

우리 버전에서는 특정 JS/Next/Supabase에 고정하지 않고 언어/프레임워크 중립적으로 재작성합니다.

### testing

ECC `tdd-workflow`의 RED/GREEN/evidence 원칙은 참고하되 다음은 가져오지 않습니다.

- 모든 작업에서 무조건 TDD
- 전역 80% coverage 강제
- 매 단계 Git checkpoint 강제

우리 정책:

- bug -> 재현 테스트 우선
- 신규 핵심 로직 -> focused unit/integration test
- 기존 Repository coverage 기준이 있으면 준수
- 기준이 없으면 임의 80% 강제하지 않음

### root-cause-debugging

- 증상과 원인 분리
- 재현 확보
- 가설을 작게 세움
- Evidence로 하나씩 제거
- 임시 workaround를 root cause fix로 보고하지 않음

### code-review

- diff/contract 중심
- correctness/regression/security/verification gap 우선
- style-only nit은 낮은 우선순위
- 수정 범위 밖 architecture 재설계 금지
