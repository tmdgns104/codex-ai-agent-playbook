## 재작성 원칙

## Skill별 정책

### security-review

- auth/authz
- input validation
- secret handling
- injection
- sensitive data
- dependency/security boundary
- sensitive action은 STRICT/Human Gate로 handoff

### testing

ECC `tdd-workflow`의 RED/GREEN/evidence 개념은 참고하지만 다음은 제거했습니다.

- 모든 작업에서 무조건 TDD
- 전역 80% coverage 강제
- 매 단계 Git checkpoint 강제

현재 정책:

- bug -> 재현 테스트 우선
- 신규 핵심 로직 -> focused unit/integration/E2E 선택
- 기존 Repository coverage 기준이 있으면 준수
- 기준이 없으면 임의 80% 강제하지 않음
- 실제 실행 Evidence만 PASS로 인정

### root-cause-debugging

- 증상과 원인 분리
- 최소 재현
- 가설을 작게 세움
- Evidence로 하나씩 제거
- workaround와 root cause fix 구분

### code-review

- diff/contract 중심
- correctness/regression/security/verification gap 우선
- style-only nit은 낮은 우선순위
- 수정 범위 밖 architecture 재설계 금지
