## 목적

사용자가 Skill 이름이나 bridge 절차를 몰라도 작업 문장 한 번만 입력하면:

```text
Task
 -> deterministic Router
 -> 최소 Skill 자동 선택
 -> activation policy
 -> task-scoped discovery bridge
 -> Codex 새 세션 실행
 -> 동일 Task를 초기 Prompt로 전달
 -> Codex 종료 후 managed cleanup
```

까지 수행하는 one-command launcher를 구현합니다.

`/skills` 수동 조작은 검증/진단용이며 정상 사용 흐름이 아닙니다.

## 구현

추가:

```text
harness/activation/playbook_launch.py
harness/activation/test_playbook_launch.py
```

기본 사용:

```cmd
python harness\activation\playbook_launch.py --root . --task "JWT 인증 오류를 수정하고 regression test를 실행"
```

사용자는 Skill을 직접 지정하지 않습니다.

## 자동 선택

대표 JWT/regression Task는 Router가 다음 3개 Skill을 자동 선택했습니다.

```text
security-review
testing
root-cause-debugging
```

`README 오타 한 줄 수정` 같은 trivial Task는 Skill 0개 / bridge 없음으로 처리합니다.

## Gate 유지

자동 Skill 선택과 권한 자동 승인은 분리합니다.

- `AUTO_ALLOWED` / 허용된 `PROFILE_GATED` Skill -> launcher 진행 가능
- `NETWORK_REVIEW` -> launch 차단
- `HUMAN_GATE_REQUIRED` -> launch 차단
- `MANUAL_ONLY` -> launch 차단

GitHub external write, credential, network/manual capability를 one-command UX가 우회하지 않습니다.

## Prompt / Process 계약

- `subprocess` argv list 사용 / `shell=True` 사용 안 함
- 사용자 Task는 `--` 뒤 positional Prompt 한 개로 정확히 한 번 전달
- child exit code 전달
- 정상/비정상/spawn 실패 후 managed bridge cleanup 시도
- `--keep-runtime`은 디버깅용 opt-in
- `--dry-run`은 Codex를 실행하지 않고 계획/argv만 출력한 뒤 기본 cleanup
