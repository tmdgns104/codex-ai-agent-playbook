## 목적

사용자가 Skill 이름이나 bridge 절차를 몰라도 작업 문장 한 번만 입력하면:

```text
Task
 -> deterministic Router
 -> 최소 Skill 자동 선택
 -> activation policy
 -> task-scoped discovery bridge
 -> Codex 새 세션 실행
 -> 동일 Task를 초기 Prompt로 전달
 -> Codex 종료 후 managed cleanup
```

까지 수행하는 one-command launcher를 구현합니다.

`/skills` 수동 조작은 검증/진단용이며 정상 사용 흐름이 아닙니다.

## 구현

추가:

```text
harness/activation/playbook_launch.py
harness/activation/test_playbook_launch.py
```

기본 사용:

```cmd
python harness\activation\playbook_launch.py --root . --task "JWT 인증 오류를 수정하고 regression test를 실행"
```

사용자는 Skill을 직접 지정하지 않습니다.

## 자동 선택

### Skill이 필요한 Task

Router가 자동 선택한 eligible Skill만 CAP-006 bridge에 노출합니다.

대표 JWT/regression Task:

```text
security-review
testing
root-cause-debugging
```

### Skill이 필요 없는 Task

예: README 오타 한 줄 수정

- Skill 0개 허용
- bridge를 만들지 않음
- Repository root를 Codex cwd로 사용
- Task Prompt는 그대로 Codex에 전달

## Gate 유지

자동 Skill 선택과 권한 자동 승인은 분리합니다.

- `AUTO_ALLOWED` / 허용된 `PROFILE_GATED` Skill -> launcher 진행 가능
- `NETWORK_REVIEW` -> `NETWORK_REVIEW_REQUIRED`로 launch 차단
- `HUMAN_GATE_REQUIRED` -> launch 차단
- `MANUAL_ONLY` -> launch 차단

따라서 GitHub external write, credential, network/manual capability를 one-command UX가 우회하지 않습니다.

## Codex Prompt 전달

Codex 현재 CLI 계약:

```text
codex [OPTIONS] [PROMPT]
```

사용자 Task는 옵션으로 해석되지 않도록 항상 option terminator `--` 뒤의 단일 positional argument로 전달합니다.

Skill bridge Task:

```text
codex -C <bridge-cwd> --add-dir <repo> -- "<task text>"
```

Skill 0 Task:

```text
codex -C <repo> -- "<task text>"
```

Task 내용을 재작성하거나 중복 삽입하지 않습니다.

## Launch / Cleanup 정책

- launcher 호출 자체를 사용자의 명시적 Codex 실행 의도로 간주
- `subprocess` argv list 사용 / `shell=True` 사용 안 함
- child exit code 전달
- 정상/비정상/spawn 실패 후 managed bridge cleanup 시도
- `--keep-runtime`은 디버깅용 opt-in
- `--dry-run`은 Codex를 실행하지 않고 계획/argv만 출력한 뒤 기본 cleanup

## 자동 Session ID

`--session` 생략 시:

```text
launch-<8 hex>
```

형태의 안전한 session id를 생성합니다.

## Acceptance Criteria

1. trivial Task -> Skill 0, bridge 없음
2. JWT/regression Task -> selected Skill exactly 3
3. Skill은 Router가 자동 선택하며 CLI에 Skill 지정 옵션이 없음
4. Task Prompt는 정확히 한 번 argv에 포함
5. `--` 뒤 positional Prompt로 전달
6. JWT launch argv가 CAP-006 `-C bridge-cwd --add-dir repo` 계약 유지
7. trivial launch argv가 repository root cwd 사용
8. dry-run은 Codex process를 실행하지 않음
9. child exit code 전달
10. 정상/실패 launch 후 managed cleanup
11. `--keep-runtime` opt-in 시 runtime 유지
12. Human/Network/Manual Gate 우회 없음
13. 기존 Router/Manager/Materializer/Bridge 회귀 없음
14. Harness Audit PASS
15. STRICT Quality Gate PASS
16. final working tree clean
