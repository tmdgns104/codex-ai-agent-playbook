## 목적

사용자가 Skill 이름이나 bridge 절차를 몰라도 작업 문장 한 번만 입력하면:

```text
Task
 -> deterministic Router
 -> 최소 Skill 자동 선택
 -> activation policy
 -> task-scoped discovery bridge
 -> Codex 새 세션 실행
 -> 동일 Task를 초기 Prompt로 전달
 -> Codex 종료 후 managed cleanup
```

까지 수행하는 one-command launcher를 구현합니다.

`/skills` 수동 조작은 검증/진단용이며 정상 사용 흐름이 아닙니다.

## 사용자 계약

기본 사용:

```cmd
python harness\activation\playbook_launch.py --root . --task "JWT 인증 오류를 수정하고 regression test를 실행"
```

사용자는 Skill을 직접 지정하지 않습니다.

### Skill이 필요한 Task

Router가 자동 선택한 eligible Skill만 CAP-006 bridge에 노출합니다.

예:

```text
security-review
testing
root-cause-debugging
```

### Skill이 필요 없는 Task

예: README 오타 한 줄 수정

- Skill 0개 허용
- bridge를 만들지 않음
- Repository root를 Codex cwd로 사용
- Task Prompt는 그대로 Codex에 전달

## Codex Prompt 전달

Codex 현재 CLI 계약은:

```text
codex [OPTIONS] [PROMPT]
```

입니다.

사용자 Task는 옵션으로 해석되지 않도록 항상 option terminator `--` 뒤의 단일 positional argument로 전달합니다.

예:

```text
codex -C <cwd> --add-dir <repo> -- "<task text>"
```

Task 내용을 재작성하거나 중복 삽입하지 않습니다.

## Launch / Cleanup 정책

- launcher 호출 자체를 사용자의 명시적 Codex 실행 의도로 간주
- Codex process spawn 외 capability side effect를 새로 실행하지 않음
- child exit code를 launcher exit code로 전달
- Codex 정상/비정상 종료 후 managed bridge 자동 cleanup
- spawn 실패도 cleanup 시도
- `--keep-runtime`은 디버깅용 opt-in
- `--dry-run`은 Codex를 실행하지 않고 계획/argv만 출력한 뒤 기본 cleanup

## Runtime 구조

Skill이 선택된 경우 CAP-006 구조를 그대로 재사용합니다.

```text
.playbook-runtime/<session>/cwd/.agents/skills/<selected-skill>/
```

새 discovery 로직을 중복 구현하지 않습니다.

## 자동 Session ID

`--session`을 생략하면 충돌 가능성이 낮은 안전한 launcher session id를 생성합니다.

형식 예:

```text
launch-a1b2c3d4
```

`--session`을 명시하면 기존 session validation 계약을 그대로 사용합니다.

## 출력

Launch 직전 최소 정보:

```text
PROFILE     STRICT
SKILLS      security-review,testing,root-cause-debugging
COUNT       3
BRIDGE      true
DRY_RUN     false
```

Codex 종료 후:

```text
CODEX_EXIT  0
CLEANUP     CLEANED
RESULT      COMPLETE
```

Skill 0개면:

```text
PROFILE     MINIMAL
SKILLS      none
COUNT       0
BRIDGE      false
```

## Safety

- Skill 직접 사용자 지정 옵션 없음
- Router bypass 없음
- 사용자 Task를 shell string으로 실행하지 않음
- `subprocess` argv list 사용
- Task는 `--` 뒤 positional prompt 한 개
- global `~/.agents/skills` write 없음
- repository root optional Skill install 없음
- MCP/Agent 자동 활성화 없음
- Human Gate capability를 launcher가 우회하지 않음
- destructive/production 권한 확대 없음
- `.codex/AGENTS.md` 확대 없음

## Allowed

- `harness/activation/playbook_launch.py`
- focused tests
- MANIFEST
- CAP-007/PR 문서

## Forbidden

- Skill 수동 선택을 정상 UX로 요구
- Router score 의미 변경
- CAP-006 discovery contract 변경
- shell=True
- user task를 CLI option으로 연결
- global/project permanent Skill install
- MCP/Agent spawn
- credential/external/database write 자동 승인
- production/destructive 자동 승인

## Acceptance Criteria

1. trivial Task -> Skill 0, bridge 없음
2. JWT/regression Task -> selected Skill exactly 3
3. Skill은 Router가 자동 선택하며 CLI에 Skill 지정 옵션이 없음
4. Task Prompt는 정확히 한 번 argv에 포함
5. `--` 뒤 positional Prompt로 전달
6. JWT launch argv가 CAP-006 `-C bridge-cwd --add-dir repo` 계약 유지
7. trivial launch argv가 repository root cwd 사용
8. dry-run은 Codex process를 실행하지 않음
9. child exit code 전달
10. 정상/실패 launch 후 managed cleanup
11. `--keep-runtime` opt-in 시 runtime 유지
12. 기존 Router/Manager/Materializer/Bridge 회귀 없음
13. Harness Audit PASS
14. STRICT Quality Gate PASS
15. final working tree clean
