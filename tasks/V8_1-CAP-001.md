# V8_1-CAP-001 - Capability Registry Baseline

상태: **APPROVED - READY FOR IMPLEMENTATION**

부모:

- `V8_1_REQUIREMENTS.md`
- `V8_1_ARCHITECTURE.md`
- `V8_1_CAPABILITY_POLICY.md`
- `V8_1_EVALUATION_PLAN.md`

## 목적

V8.1의 첫 구현 단계로 Capability Library의 metadata registry와 deterministic validator를 추가합니다.

이 Task에서는 실제 MCP 연결, Agent spawn, 외부 write, credential 사용을 구현하지 않습니다.

## Allowed

- `capability-library/registry.json`
- `capability-library/sources.json`
- `harness/router/registry.py` 또는 동등한 단일 registry validator 모듈
- registry validator 테스트/fixture
- `harness/security/harness_audit.py`의 registry 검증 연동
- `MANIFEST.txt` 갱신
- V8.1 관련 문서/Task 상태 갱신

## Forbidden

- `.codex/AGENTS.md` 확대
- 기존 V8 Quality Gate 의미 변경
- 실제 MCP config 변경
- MCP 서버 설치
- Agent 자동 실행
- credential/external-write/database-write/destructive capability 활성화
- 기존 7개 Core Skill의 책임을 임의 변경

이 Task에서는 Capability 본문을 반드시 모두 구현할 필요는 없습니다. Registry/validator 검증이 우선입니다.

## Validator 요구사항

최소 검사:

- JSON parse
- top-level schema
- required fields
- unique `id`
- enum validity
- non-empty summary/domains
- permissions enum
- dependencies가 알려진 id를 참조하는지
- `source_id`가 `sources.json`에 존재하는지
- optional capability path가 허용된 Library root 아래인지
- absolute/personal path 금지

## Harness Audit 연동

기존 `harness_audit.py` 결과에 다음과 같은 항목이 추가되어야 합니다.

```text
PASS       capability registry
PASS       capability sources
```

잘못된 registry fixture에서는 FAIL이어야 합니다.

## Acceptance Criteria

1. 정상 registry validator exit 0
2. duplicate id fixture FAIL
3. invalid permission fixture FAIL
4. unknown source fixture FAIL
5. personal absolute path fixture FAIL
6. 기존 Harness Audit 검사 유지
7. `MANIFEST.txt`에 새 managed files 반영
8. 기존 V8 Quality Gate 의미/출력 계약을 깨지 않음

## Verification

구현 후 최소 실행:

```cmd
python harness\router\registry.py --root .
python harness\security\harness_audit.py --root .
python harness\quality\quality_gate.py --repo . --profile strict --verify "python harness\security\harness_audit.py --root ."
```

실제 실행하지 않은 검증은 PASS로 기록하지 않습니다.
