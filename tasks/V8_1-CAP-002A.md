## 발견 배경

실제 Windows 검증 문장:

```text
JWT 인증 오류를 수정하고 regression test를 실행
```

에서 Router가 다음을 선택했습니다.

```text
security-review
code-review
testing
```

기능적으로는 CAP-002 Acceptance Criteria를 통과했지만, V8.1의 최우선 목표인 최소 Capability 선택 관점에서 두 문제가 확인되었습니다.

1. 한국어 조사 때문에 `오류를`, `test를` 같은 토큰에서 `오류`, `test` trigger를 놓침
2. `code-review`가 `regression/회귀`를 직접 trigger로 가져 testing과 책임이 겹쳐 false activation 가능성이 있음

## 목적

한국어 사용자 요청에서 조사 접미사가 붙어도 핵심 trigger를 안정적으로 인식하고, testing과 code-review의 trigger 책임을 분리해 불필요한 Capability 선택을 줄입니다.

## Matching 정책

영문/일반 token은 기존 exact boundary match를 유지합니다.

한국어 또는 영문 trigger 뒤에 한국어 조사가 붙은 경우에만 보조 match를 허용합니다.

초기 허용 조사 예:

```text
은 는 이 가 을 를 에 에서 로 으로 과 와 의 도 만 부터 까지
```

예:

```text
오류 -> 오류를   MATCH
test -> test를   MATCH
보안 -> 보안관   NO MATCH
pr -> problem    NO MATCH
```

## Trigger 책임 조정

`code-review`에서 다음 trigger를 제거합니다.

```text
regression
회귀
```

회귀 테스트 자체는 `testing`이 담당하고, code-review는 `review/diff/refactor/quality/리뷰/검토/리팩터링/품질`처럼 직접 리뷰 의도가 있을 때 선택합니다.

## Acceptance Criteria

1. `오류를`이 `root-cause-debugging`의 `오류` trigger와 match
2. `test를`이 `testing`의 `test` trigger와 match
3. `보안관`이 `보안` trigger로 오인되지 않음
4. `problem`이 `pr` trigger로 오인되지 않음
5. 실제 검증 문장에서 `code-review`가 불필요하게 선택되지 않음
6. 실제 검증 문장에서 `security-review`, `testing`, `root-cause-debugging` 선택
7. 최종 profile STRICT 유지
8. 기존 12개 Router 테스트 회귀 없음
9. Harness Audit PASS
10. STRICT Quality Gate PASS
11. working tree clean
